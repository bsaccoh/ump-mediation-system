Execution companion for the drive_test module overhaul. Keep this open while working.

## Non-negotiable invariants

Check every change against this list.

| # | Rule |
|---|---|
| 1 | **No mock data.** No fake sessions, operators, sites, measurements, cells, findings, KPIs, map points or charts. Empty state instead. |
| 2 | **Missing is not zero.** No MOS / no throughput / no GPS / no voice records all render `—`, never `0`. |
| 3 | **Unknown stays UNKNOWN.** Detection never infers an unsupported value as fact. |
| 4 | **Never fabricate a field the source lacks.** BSIC, PSC, ARFCN, NCI, MOS, throughput, IMS, protocol messages — if absent, show "Not available in source data." |
| 5 | **Raw is never overwritten.** `obs_*` fields stay as parsed. Derived values go elsewhere and are labelled derived. |
| 6 | **Observed ≠ Authoritative ≠ Derived.** Observed serving cell ≠ matched reference cell. Measured RSRP ≠ regulatory classification. Coverage polygons are always labelled *Derived / Estimated*. |
| 7 | **No hard-coded regulatory thresholds** in templates or JavaScript. They come from `RegulatoryThreshold`. |
| 8 | **Backend is the source of truth** for KPIs, regulatory evaluation, cell matching, data quality, findings, compliance. JS only visualises. |
| 9 | **Do not change KPI semantics.** `services/kpi.py` formulas stay as they are. |
| 10 | **Do not modify the three shared decorators** in `core/decorators.py` — they also gate the `regulatory` app. |
| 11 | **Do not break CDR mediation.** No new imports between `drive_test` and `collection`/`streams`/`dashboard`. |
| 12 | **Do not change `USE_TZ`.** It is load-bearing for CDR mediation. Use the existing `_naive()` helper at every new boundary. |
| 13 | **No React, no Tailwind.** Django templates + Bootstrap 5.3.3 + Leaflet 1.9.4 + Chart.js 4.4.0. |
| 14 | **Geography is not inferred.** Region/district derive via matched cell → site → region. No matched cell means no geography, not a guess. |
| 15 | **Data-quality problems are not network findings.** Keep them separate. |

### Regression net structure

`drive_test/tests/regression/`, settings-driven corpus path, `SkipTest` (not failure) when the files are
absent so CI without the corpus stays green.

| Tier | Asserts |
|---|---|
| **1 · Golden summary** | Per file, against committed JSON: `Measurement` count; GPS-fix count; counts per `match_method` and confidence tier; `ServiceMeasurement` by type and outcome; event counts by type; min/max/mean to 2dp **and a null-count per field** for rsrp/rsrq/sinr/rscp/ecio/throughput; min/max lat/lon; first/last timestamp; distinct `(mcc,mnc,lac,ci)` and `(tac,eci)` set sizes; sorted `quality_flags` histogram |
| **2 · Golden rows** | ~20 measurements per file pinned by stable ordinal, every field incl. `obs_*`. Catches provenance regressions where aggregates match but A/B/C attribution flips |
| **3 · Parser-level** | Hash the `parse()` stream (`dataclasses.asdict`, sorted keys), no DB. Isolates parser from persistence regressions. Changes exactly once when the dataclass widens |
| **4 · Idempotency + 5G** | Re-ingest the same file twice, assert dedup. Plus a **synthetic 5G fixture** asserting the SS fields survive `_flush_chunk` — the TRP corpus cannot cover this |

> **The null-counts in Tier 1 are what catch the `ss_rsrp` class of bug.** Means alone will not — the mean of
> an all-null column is simply absent.

### New models (migration 0006)

Each carries the A/B/C provenance pattern already proven on `Measurement`.

| Model | Shape |
|---|---|
| `NeighbourMeasurement` | FK measurement · `rank` · `rat` · `pci`/`psc`/`bsic` · `arfcn` · `rsrp`/`rsrq`/`rscp`/`ecio`/`rssi`/`ss_rsrp` · nullable `cell` FK · own `match_confidence`/`match_method` · `unique_together (measurement, rank)` |
| `MeasurementEvent` | FK **session** + *nullable* FK measurement · `timestamp` · `event_type` · `severity` · denormalised `lat`/`lon` · `payload` JSON · index `(session_id, timestamp)` |
| `CarrierMeasurement` | FK measurement · `cc_index` · `is_primary` · `arfcn` · `band` · `bandwidth_mhz` · `rsrp`/`rsrq`/`sinr` · `mimo_layers` · `modulation` · `dl_mbps` |
| `BeamMeasurement` | FK measurement · `ssb_index` · `ss_rsrp`/`ss_rsrq`/`ss_sinr` |

**Rules:**
- `RadioMeasurement` is **not** widened — it stays the serving-cell scalar row.
- `HandoverEvent` is deprecated-by-superset: keep writing it, make `MeasurementEvent` the read path, backfill,
  remove two releases later. **Never** migrate it in the same change that introduces the reader.
- New FKs to `reference.Operator` must pick unused `related_name`s — `drive_test_sessions` and
  `regulatory_thresholds` are already claimed, and a collision fails system checks project-wide.

### Parser contract

```python
@dataclass
class ParsedMeasurement:
    # ... all existing fields unchanged ...
    neighbours: list[ParsedNeighbour] = field(default_factory=list)
    events:     list[ParsedEvent]     = field(default_factory=list)
    carriers:   list[ParsedCarrier]   = field(default_factory=list)
    beams:      list[ParsedBeam]      = field(default_factory=list)


class DriveTestParser:
    extensions:   list[str]
    magic_bytes:  str
    capabilities: ParserCapabilities          # supports_neighbours / _events / _l3 / _carriers

    def parse(self, path)        -> Generator[ParsedMeasurement]
    def parse_events(self, path) -> Generator[ParsedEvent]:  return ()   # default
    @classmethod
    def sniff(cls, fh) -> float               # 0.0–1.0 confidence
```

`csv_parser` and `trp_parser` are untouched — they construct without the new kwargs and get empty lists.
Zero behaviour change, provable by the Tier 3 hash.

`parse_events()` exists because `.nmf` and `.qmdl` are **message-oriented** — L3 signalling arrives decoupled
from sample cadence. Without it you must invent a carrier measurement for every SIB.

`ParserCapabilities` lets the UI say *"this format carries no neighbour data"* instead of showing an empty
panel that looks like a bug.

### Wire format

```
GET /drive-test/api/sessions/<ref>/timeseries/?metrics=rsrp,sinr,dl&from=&to=

{
  "t":    [...],            // relative ms from session start
  "lat":  [...], "lon": [...],
  "rsrp": [...], "sinr": [...], "dl_kbps": [...],
  "tech": [...],            // small-int coded
  "cell": [...],
  "events": [ {"t": 84210, "type": "HO_SUCCESS", "idx": 1421} ],
  "meta": { "decimated": true, "source_count": 412000, "returned": 4000,
            "available_metrics": ["rsrp","rsrq","sinr","dl_kbps"],
            "absent_metrics":    ["ss_rsrp","mos"] }
}
```

Column arrays, not row objects. 410 rows today, 400k later — the format must not need to change.
`absent_metrics` is what lets a pane render *"not available in source data"* rather than an empty chart.

### Client architecture

No build step, no ES modules. One controller IIFE owning state, broadcasting `CustomEvent` on the workspace
root. The DOM is the event bus.

```
dt-workspace.js    the ONLY stateful module
                   owns { sessionRef, cursorIndex, selection{t0,t1}, activeMetric, filters }
                   + the fetched column arrays

                   mutators (the only way state changes):
                     setCursor(index) · setSelection(t0,t1) · setMetric(key)

                   dispatches on #dt-workspace:
                     dt:data-loaded · dt:cursor · dt:selection · dt:metric

dt-map.js          ┐
dt-charts.js       │  pure subscribers. Read e.detail, never each other.
dt-timeline.js     │  Call mutators on user interaction.
dt-detail.js       ┘  Strictly unidirectional: intent up, state down.

dt-util.js         the one home for el(), fmt(), colour scales, decimation.
                   Loaded first. Delete the 7 copy-pasted helpers opportunistically.
```

**Three rules that stop this rotting:**
1. Mutators are idempotent and re-entrancy-guarded — map pan → cursor → map fit is the obvious infinite loop.
2. `dt:cursor` is rAF-coalesced — mouse-move fires continuously; the map must not re-render per event.
3. **Every event carries a sample index, not a timestamp** — panes never re-search, which removes an entire
   class of off-by-one desync.

## Platform constraints

### Coupling surface — what drive_test shares

`drive_test` imports **nothing** from `collection/`, `streams/*`, `dashboard/`, `businesslogic/`, `portals/`,
`scripts/` or `regulatory/`. Inbound references are three wiring lines plus the sidebar and one nginx location.

| Shared object | Constraint |
|---|---|
| `reference.Operator` | PROTECT FK. Audit `related_name` before adding any new FK |
| `core.User` | `AUTH_USER_MODEL` FKs on session / finding / report |
| `core.AuditLog` | drive_test writes here via `services/audit.py` — never a second audit system |
| `core.JobRecord` | FK from `DriveTestFile.job` |
| `core.decorators` | `analyst_required`, `regulator_required`, `regulatory_admin_required` — **also gate the regulatory app.** Never edit; add new gates if needed |

### Naming hazard

`RegulatoryRule`, `RegulatoryThreshold`, `RegulatoryReport` and `Finding` live in **drive_test**, not the
regulatory app. The regulatory app has its own unrelated `AuditFinding`, `RiskRule`, `AuditCaseReport`.
Never "consolidate regulatory models into the regulatory app" — it breaks drive_test.

### Database

All drive_test models route to `default` (the CDR control-plane DB) via `config/db_router.py`. No operator
isolation — multi-operator data is separated only by `DriveTestSession.operator`. Volume growth is
shared-resource contention on disk/IO/vacuum. Revisit partitioning past ~10M measurements.

### Geospatial

GeoDjango/GDAL are **not installed**. Keep `FloatField` lat/lon behind a `GeoQueryService` interface:

```
views → GeoQueryService → ORM
                        ↑ swappable

Now:   FloatField + bbox filter + existing (latitude, longitude) index
Later: PointField + GiST + ST_ functions, behind the same interface
Trigger: >1M measurements, or the first coverage-polygon feature
```
