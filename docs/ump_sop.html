1   Purpose & Scope

This SOP provides the step-by-step procedures required to configure the Universal Mediation Platform (UMP) for production service. It covers all UI-configurable services from initial reference data provisioning through to end-to-end CDR distribution.

The document is organized in the order a new deployment should be configured:

  1. Reference Data — Operators, source patterns, numbering plan, MCC/MNC, IMSI prefixes, trunk groups, vendors
  2. Portals & Collection — Data sources, input portals, output portals, output schemas, distribution rules
  3. Processing Services — File upload, decoder, distributor, collector daemons
  4. Business Logic — Validation, enrichment, transformation, filtering rules
  5. Operations — Dashboard, file registry, reports, user management
Note
This SOP assumes the application has been deployed and the database schema has been applied via python manage.py migrate. For installation procedures, refer to the Deployment Guide (SOP-UMP-DEP-001).

3   System Architecture

The UMP platform is composed of a Django web application for configuration and monitoring, and three long-running background services for automated CDR processing:

ComponentTypeFunction
Web ApplicationGunicorn + NginxConfiguration UI, file upload, dashboards, reports, admin panel
CollectorSystemd daemonPolls input portals (SFTP/FTP/local) for new CDR files
DecoderSystemd daemonDecodes collected files (ASN.1, CSV, etc.) into normalized records
DistributorSystemd daemonDelivers decoded files to output portals per distribution rules

5   Reference Data Configuration

Reference data must be provisioned before files can be processed. Configure in the order presented below, as later steps depend on earlier data.

Navigation: Sidebar → Reference Data → select the subsection.

5.1   Operators

An Operator represents a mobile network tenant. Multi-operator deployments require one record per operator. The operator code determines the per-operator directory tree and database routing.

Path: Reference Data → Operators → + Add Operator

Caution
The code field determines the directory structure (data/{code}/input/...). Changing it after files have been processed will orphan existing files on disk. Plan the code value before going live.

5.2   Source Patterns

Source Patterns map incoming filenames to an operator, vendor, network element, and decoder type. When a file is uploaded or collected, its filename is matched against all enabled patterns in priority order (lowest first); the first match wins.

Path: Reference Data → Source Patterns → + Add Pattern

vendorSlug RequiredEquipment vendor slug (used in directory path)huawei
network_elementChoice RequiredStream type: msc, ims, pgw, sgsn, sgw, cbs, ocsmsc
decoder_typeChoiceDecoder: MSC, IMS, PGW, SGSN, SGW, CBS, CSV, FORWARD, or AUTOMSC
priorityIntegerLower values are tried first. Default: 10010

Procedure: Add a Source Pattern for Huawei MSC

1

Navigate to Reference Data → Source Patterns.

2

Click + Add Pattern.

3

Enter pattern: HMSC (matches any filename containing "HMSC").

4

Select Operator: Orange Sierra Leone.

5

Set Vendor: huawei, Network Element: msc, Decoder: MSC.

6

Set Priority: 10. Ensure Enabled is checked.

7

Click Save. The pattern now appears in the list.

Note
If decoder_type is set to AUTO, the system will attempt to detect the decoder type from the filename and file content. For best results, set the decoder type explicitly.

6.4   Output Schemas

Output Schemas define the column mapping and file format for distributed CDR files. Each Distribution Rule links to an Output Schema to control which fields are exported and how they are named.

Path: Admin Panel → System & Portals → Output Schemas → Add Output Schema

FieldTypeDescriptionExample
nameText RequiredSchema nameMSC-BIGDATA-SCHEMA
stream_typeChoiceMSC, IMS, PGW, SGSN, SGW, CBS, ALLMSC
mapping_jsonJSONColumn mapping: {"OutputHeader": "db_field"} or [["Header", "field"], ...]See below
delimiterTextCSV field delimiter,
include_headerBooleanInclude header row in outputTrue
quote_allBooleanQuote all CSV fieldsFalse
line_terminatorTextLine ending: \n (Unix) or \r\n (Windows)\n

Mapping JSON Format

Two formats are supported:

Dict format (column order not guaranteed):

{
  "MSISDN": "subscriber_id",
  "CALLED_NUMBER": "called_number",
  "DURATION": "call_duration",
  "START_TIME": "answer_time"
}

List format (preserves column order, recommended):

[
  ["MSISDN", "subscriber_id"],
  ["CALLED_NUMBER", "called_number"],
  ["DURATION", "call_duration"],
  ["START_TIME", "answer_time"]
]
Note
If mapping_json is empty ({}), all model fields are exported in declaration order. Use the list format for downstream systems that require a specific column order.

6.6   Pass-Through / Forward Mode

For downstream systems that receive files without decoding (e.g., raw billing feeds, flat files), UMP supports a pass-through mode. Files are collected, classified, and forwarded as-is without any decoding or record extraction.

Configuration Requirements

ComponentSettingValue
Source Patterndecoder_typeFORWARD (Pass-through)
Data Sourcedecoder_typeFORWARD
Output Portaloutput_formatRAW (Raw Binary)
Output Schemamapping_json{} (empty, ignored for RAW)
Distribution Rulestream_typeFORWARD
Note
When a file’s decoder_type is FORWARD, the Decoder service immediately marks it as DECODED without processing. The Distributor then delivers the original file byte-for-byte to any matching Distribution Rule with output_format = RAW.

7   Processing Services

7.1   Manual File Upload

CDR files can be manually uploaded through the web UI for ad-hoc processing or testing.

Path: Sidebar → Operations → File Upload

1

Navigate to Operations → File Upload.

2

Click Choose Files to select one or more CDR files. Accepted formats: .dat, .bin, .csv, .txt, .asn1.

3

Input Source (optional): Select a Data Source to associate. If left as “Auto-detect”, the system resolves the source from the file’s decoder type.

4

Decoder Type (optional): Override the auto-detected decoder. Leave as “Auto-detect” for most cases.

5

Click Upload & Process. The file enters the pipeline with status COLLECTED.

Note
Uploaded files are classified using Source Patterns. Ensure a matching pattern exists before uploading; otherwise the file’s operator/vendor/network_element fields will be empty.

SGW3GPP SGW CDRs (4G S-GW)SGWRecord

FORWARDPass-through (no decoding)None (file forwarded as-is)

Starting the Decoder

# Development (foreground)
python manage.py run_decoder --batch 10 --interval 5

# Production (systemd)
sudo systemctl start mediation-decoder
sudo systemctl enable mediation-decoder
ParameterDescriptionDefault
--batchMax files to process per cycle10
--intervalSeconds between poll cycles when idle10 (or SERVICE_POLL_INTERVAL)

7.3   Distributor Service

The Distributor picks up files with status DECODED and evaluates all active Distribution Rules. For each matching rule, it renders the output per the Output Schema and delivers via the Output Portal’s transport.

Starting the Distributor

# Development (foreground)
python manage.py run_distributor --batch 10 --interval 10

# Production (systemd)
sudo systemctl start mediation-distributor
sudo systemctl enable mediation-distributor

7.4   Collector Service

The Collector polls enabled Data Sources (SFTP, FTP, local directories) for new files matching the configured file patterns. Collected files are downloaded to the local staging area and registered as CDRFile records with status COLLECTED.

Starting the Collector

# Development (foreground)
python manage.py run_collector --interval 60

# Production (systemd)
sudo systemctl start mediation-collector
sudo systemctl enable mediation-collector

Additional specialized rule types are available under the Business Logic submenu:

  • Correlation Rules — Match related CDRs across streams (e.g., correlate MSC voice with IMS VoLTE)
  • Detection Rules — Identify anomalies such as short-duration calls, silent periods, or volume spikes
  • Error Handling — Define how specific error conditions are handled (retry, skip, escalate)

8.2   Scripts IDE

The Scripts IDE allows authorized administrators to write and test Python scripts for advanced CDR processing logic that cannot be expressed as declarative rules.

Path: Sidebar → Configuration → Scripts

Warning
The Scripts IDE executes arbitrary Python code on the server. Access is restricted to superuser accounts only. Scripts run with full application context. Always test scripts in a development environment before deploying to production.
